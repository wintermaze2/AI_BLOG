 메일링크 기술 블로그 - 본문 HTML 작성 지침서
 (Claude / ChatGPT 등에게 글 본문을 HTML로 만들어 달라고 할 때 사용)

 대상 : https://tech.maillink.co.kr
 최종 수정 : 2026-08-14
================================================================================

이 블로그는 글 본문을 "완결된 HTML 문서"가 아니라 "본문 조각"으로 받습니다.
LLM에게 그냥 "HTML로 만들어줘" 라고 하면 <!DOCTYPE html> 부터 시작하는 완전한
페이지를 주는데, 그걸 그대로 붙여넣으면 블로그 전체 디자인이 망가집니다.

아래 [A] 를 통째로 복사해서 LLM에게 주면 됩니다.


================================================================================
 [A]  LLM에게 그대로 붙여넣을 프롬프트
================================================================================
--------------------------------- 여기부터 ---------------------------------

아래 규칙을 지켜서 블로그 글 본문을 HTML로 작성해 주세요.
결과물은 UTF-8 로 인코딩된 .html 파일 하나로 주세요.

[문서 구조]
1. <!DOCTYPE>, <html>, <head>, <body> 태그를 쓰지 마세요.
   본문에 들어갈 조각만 출력합니다. 블로그가 이미 페이지 틀을 갖고 있습니다.
2. <h1> 을 쓰지 마세요. 글 제목은 블로그가 따로 렌더링합니다.
   본문의 최상위 제목은 <h2> 로 시작하고, 그 아래는 <h3>, <h4> 순으로 씁니다.
3. 제목/요약/태그를 본문 안에 다시 넣지 마세요.
   블로그가 제목, 작성일, 카테고리, 태그를 자동으로 보여줍니다.
4. <script> 를 넣지 마세요.
5. 글 맨 끝에 본문과 별개의 머리말/꼬리말(사이트명, 저작권 문구 등)을 넣지 마세요.
   단 아래 [맺음 CTA]의 블록은 예외이며, 모든 글에 반드시 넣어야 합니다.

[스타일]
6. 되도록 스타일 없이 순수한 시맨틱 태그만 쓰세요.
   블로그가 h2/h3, p, ul/ol, pre, code, img, blockquote 에 이미 스타일을 갖고 있습니다.
7. 스타일이 꼭 필요하면 <style> 블록을 본문 맨 앞에 두되,
   모든 선택자를 반드시 .post-body 하위로 한정하세요.
     좋음 :  .post-body .note { ... }
     나쁨 :  .note { ... }        <- 블로그 전체에 영향을 줍니다
8. :root { } 를 쓰지 마세요. CSS 변수를 정의하려면 .post-body { --이름: 값 } 으로 하세요.
   특히 아래 이름은 블로그가 이미 쓰고 있으므로 절대 재정의하면 안 됩니다.
     --fg  --muted  --accent  --line  --bg  --soft  --sans  --mono
   (재정의하면 헤더/푸터/목록 색까지 같이 바뀝니다)
9. 인라인 코드 스타일을 바꾸려면 반드시 아래 형태로 쓰세요.
     .post-body :not(pre) > code { ... }
   `.post-body code` 로 쓰면 블로그의 기존 규칙이 더 구체적이라 덮이지 않습니다.
10. @media (prefers-color-scheme: dark) 블록을 넣지 마세요.
    블로그가 다크모드를 지원하지 않아 본문만 검게 변합니다.
11. 웹폰트를 불러오지 마세요(@import, <link> 모두).
    Noto Sans KR(400~800)과 JetBrains Mono(400,500)가 이미 로드되어 있습니다.
    글꼴을 지정할 일이 있으면 var(--sans) / var(--mono) 를 쓰세요.

[표]
12. 표 스타일은 블로그가 이미 갖고 있습니다. 직접 만들지 마세요.
    표는 아래처럼 감싸기만 하면 됩니다. 감싸야 모바일에서 가로 스크롤이 됩니다.
      <div class="table-wrap">
        <table>
          <thead><tr><th>항목</th><th>값</th></tr></thead>
          <tbody><tr><td>...</td><td>...</td></tr></tbody>
        </table>
      </div>
13. 열이 4개 이상이라 칸이 뭉개질 것 같으면 <table class="table-wide"> 로 쓰세요.
    최소 너비가 생겨 좁은 화면에서 찌그러지지 않고 가로 스크롤됩니다.
    표 바로 아래에 안내문을 넣어 두면 모바일에서만 표시됩니다(선택).
      <p class="scroll-hint">← 표를 좌우로 밀어서 보실 수 있습니다.</p>

[코드/이미지/링크]
14. 코드 블록은 <pre><code> ... </code></pre> 로 감싸고,
    내부의 < > & 는 각각 &lt; &gt; &amp; 로 이스케이프하세요.
15. 이미지는 <img src="..." alt="설명"> 형태로, 절대 URL 또는 /static/img/파일명 을 씁니다.
    alt 는 반드시 채우되, 옆 텍스트와 내용이 겹치는 장식용 이미지는 alt="" 로 둡니다.
16. 블로그 내부 링크 경로 형식
      글      : /posts/{슬러그}
      카테고리 : /category/{슬러그}
      태그     : /tag/{슬러그}
    아직 발행하지 않은 글로 링크하면 404 입니다. 확실하지 않으면 링크하지 마세요.
17. 외부 링크는 https 전체 주소로 씁니다.

[맺음 CTA - 모든 글에 필수]
18. 모든 글은 아래 블록으로 끝나야 합니다. 본문 맨 끝에 그대로 붙여 넣으세요.
    스타일은 블로그가 갖고 있으므로 CSS를 따로 만들지 마세요.

      <div class="cta">
        <p class="cta-copy">이메일, 문자, FAX, 카카오 비즈메시지를 한 번에</p>
        <a class="cta-btn" href="https://www.maillink.co.kr?r=tech">
          메일링크 바로가기
          <svg width="16" height="16" viewBox="0 0 24 24" fill="none" stroke="currentColor"
               stroke-width="2" stroke-linecap="square" aria-hidden="true">
            <path d="M5 12h14M13 6l6 6-6 6"/>
          </svg>
        </a>
      </div>

19. 문구와 링크는 위 내용을 그대로 씁니다. 글 주제에 맞춰 바꾸지 마세요.
    (모든 글에서 같아야 하는 브랜드 문구입니다)

[함께 제출할 항목]
20. 본문과 별개로 아래 값을 같이 알려주세요. 관리자 화면 입력용입니다.
      제목       : 300자 이내
      슬러그     : 영문 소문자/숫자/하이픈 권장 (한글도 가능), 200자 이내
      요약       : 500자 이내, 목록 화면에 노출
      메타 설명  : 320자 이내, 검색결과에 노출 (비우면 요약을 사용)
      태그       : 쉼표 구분, 최대 20개, 개당 80자 이내
      카테고리   : 기존 카테고리 중 하나
      대표 이미지 URL : 선택, 500자 이내 (og:image 로 사용)

[문체]
21. 한국어 존댓말(~습니다)로 작성합니다.
22. 첫 문단에서 이 글이 무엇을 다루는지 바로 밝힙니다. 검색결과 미리보기에 쓰입니다.

================================================================================
 [B]  받은 파일 점검 체크리스트
================================================================================

붙여넣기 전에 파일을 열어 아래를 눈으로 확인하세요. 대부분의 사고가 여기서 걸러집니다.

  [ ] 파일 인코딩이 UTF-8 인가?
      -> 관리자 화면은 파일을 UTF-8 로 읽습니다. CP949(ANSI)로 저장되어 있으면
         한글이 전부 깨집니다. 메모장이면 "다른 이름으로 저장 > 인코딩: UTF-8".
  [ ] <!DOCTYPE 또는 <html 또는 <body 로 시작하지 않는가?
  [ ] <h1> 이 없는가?
  [ ] <style> 안의 모든 선택자가 .post-body 로 시작하는가?
  [ ] :root 가 없는가?
  [ ] prefers-color-scheme 이 없는가?
  [ ] fonts.googleapis.com 같은 폰트 링크가 없는가?
  [ ] <script> 가 없는가?
  [ ] 내부 링크가 /posts/... 형식인가? 그 글이 실제로 발행되어 있는가?
  [ ] 맨 끝에 CTA 블록(div.cta)이 있고, 문구가 지정된 그대로인가?

빠르게 확인하는 방법 (Git Bash):

  1) 금지 항목 검사 - 아무것도 출력되지 않으면 통과

    perl -0777 -pe 's/<!--.*?-->//gs' 파일명 | grep -nE "<!DOCTYPE|<html|<body|<h1|:root|prefers-color-scheme|fonts\.googleapis|<script"

    앞의 perl 은 HTML 주석을 지웁니다. 이걸 빼고 grep 만 쓰면 주석에 적힌
    설명 문구까지 걸려서 오탐이 납니다.

  2) 인코딩 검사 - charset=utf-8 로 나와야 함

    file -i 파일명

  3) 스타일 선택자가 전부 .post-body 하위인지 검사
     (<style> 안에서 .post-body 로 시작하지 않는 선택자를 찾습니다)

    perl -0777 -ne 'while(/<style>(.*?)<\/style>/gs){ $c=$1; $c=~s{/\*.*?\*/}{}gs;
      while($c=~/([^{}]+)\{/g){ $s=$1; $s=~s/^\s+|\s+$//g;
        next if $s=~/^\@/;
        for $t (split /,/,$s){ $t=~s/^\s+|\s+$//g;
          print "전역 오염 위험: $t\n" unless $t=~/^\.post-body/ || $t eq ""; } } }' 파일명

    -> 아무것도 출력되지 않으면 통과입니다.

--- 블로그가 이미 스타일을 갖고 있는 요소 (그냥 쓰면 됨) ---
  h2, h3        제목 간격과 줄높이
  p             문단 간격
  a             링크 색
  pre           어두운 배경 코드 블록, 가로 스크롤
  code          고정폭 글꼴 + 회색 배경 (pre 안에서는 배경 없음)
  img           최대 너비 100%, 모서리 둥글게
  blockquote    왼쪽 세로선 인용
  table         머리행 배경, 행 구분선, 좁은 화면에서 글자·여백 축소
                .table-wrap  으로 감싸면 가로 스크롤 (표 쓸 때 항상 권장)
                .table-wide  최소 너비 640px, 열이 많은 표에
                .scroll-hint 표 아래 안내문, 좁은 화면에서만 표시
  .cta          맺음 CTA 상자 (.cta-copy 안내문구, .cta-btn 버튼)
                모바일에서 버튼이 가로 전체로 늘어납니다

--- 스타일이 없는 요소 (필요하면 직접 넣어야 함) ---
  hr, h4 이하        브라우저 기본값
  figure, figcaption, dl 등

--- DB 길이 제한 (초과하면 저장 시 잘리거나 오류) ---
  제목 300 / 슬러그 200 / 요약 500 / 메타설명 320 / 대표이미지 URL 500
  태그 이름 80, 글당 태그 최대 20개
  본문은 사실상 제한 없음 (MEDIUMTEXT, 약 16MB)

--- 슬러그 자동 생성 규칙 ---
  비워두면 제목에서 자동 생성됩니다.
  소문자로 바꾸고, 한글/영문/숫자/하이픈만 남기고, 공백과 특수문자는 하이픈으로.
  이미 같은 슬러그가 있으면 뒤에 타임스탬프가 붙습니다.

--- 이미 로드된 웹폰트 ---
  Noto Sans KR  400~800 (가변)   -> var(--sans)
  JetBrains Mono 400, 500        -> var(--mono)


================================================================================
 [E]  왜 이런 제약이 있는가 (배경)
================================================================================

* 완결된 HTML 문서를 그대로 넣으면 왜 깨지나
  브라우저는 본문 안에 들어온 <html>, <head>, <body> 태그는 버리지만
  <style> 블록은 살려서 페이지 전체에 적용합니다. 그래서 문서가 정의한
  :root 변수와 body, h1, table 같은 태그 선택자가 블로그 공통 스타일을 덮어씁니다.
  실제로 초안 문서 하나가 --muted 를 정의하고 있었는데, 그대로 넣었으면
  본문뿐 아니라 헤더/푸터/글 목록 색까지 전부 바뀔 상황이었습니다.

* 왜 .post-body 하위로 한정하나
  본문은 <div class="post-body"> 안에 렌더링됩니다. 모든 선택자를 이 클래스
  하위로 두면 스타일이 글 안에만 갇힙니다. 여러 글을 발행해도 서로 간섭하지 않습니다.

* 왜 인라인 코드만 선택자 형태를 지정하나
  블로그가 `.post-body :not(pre)>code` 라는 구체적인 규칙을 갖고 있습니다.
  CSS는 더 구체적인 규칙이 이깁니다. 그래서 `.post-body code` 로는 덮이지 않고,
  같은 형태로 써야 의도한 스타일이 적용됩니다.

* 왜 다크모드를 빼나
  블로그 본체에 다크모드가 없습니다. 본문에만 다크모드 규칙이 있으면
  사용자가 다크 환경일 때 글 영역만 검어지고 헤더/푸터는 흰 상태로 남습니다.

* 왜 h1 을 쓰지 않나
  글 상세 화면이 제목을 <h1> 으로 이미 출력합니다. 본문에 또 h1 을 넣으면
  한 페이지에 h1 이 둘이 되어 제목 구조가 흐트러지고 검색엔진에도 좋지 않습니다.

* 실제 적용 예시
  contents/about-dmarc.html      원본 (완결된 HTML 문서 - 그대로 쓰면 안 되는 형태)
  contents/about-dmarc.body.html 위 규칙에 맞춰 변환한 결과 - 참고용으로 보세요
